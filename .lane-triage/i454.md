## Item 3 specimen: the Jev gate's FAIL line names a level, not the fact behind the number

Specimen met this session while working #445 on PR #464. Recorded rather than cured, because curing it means deciding what the number *is*.

**Command** (operator clone, `main` @ `b4b341a`, Python 3.9.25 venv):

```
python audits/self/audit.py --dim SD
```

**What it printed** - every deterministic check passes, and the gate below them fails:

```
     D1 pass MCP tool parity with README
     D2 pass CLI surface documented
     ...
    D12 pass changed lines suite-executed (coverage)
    D13 pass flush-loop canary suite passes as a gate

JEV 4-DIMENSION TRUE GATE (authoritative bar >= 9.50/10 on ALL 4 dimensions):
  [N/E] A - Security: not_evaluated
  [N/E] R - Reliability: not_evaluated
  [N/E] SM - Structural hygiene & maintainability: not_evaluated
  [LOW] SD - Documentation & release integrity: 5.00/10 (50.0%) [failing - severe defect or broken guarantee (<7.0)]
  Jev Gate Result (SD): FAIL (<95%) (is_fallback=False, model=jev-1.14.0)

scores: {'A': 10.0, 'R': 10.0, 'SM': 10.0, 'SD': 10.0}
```

**The environment fact the FAIL line does not name.** Three facts are all missing from it:

1. **The 5.00 is not arithmetic on the checks above it.** The deterministic dimension mean is 10.00 (`scores: ... 'SD': 10.0`), and the gate's own evidence dict is built from that mean (`dimension_evidence[dim]["score"] = summary[dim]`). The 5.00 is Jev's declared level for SD (`is_fallback=False, model=jev-1.14.0`), not a derivative of the 13 `pass` rows printed directly above it. A reader sees "all pass" and "5.00 failing" with nothing saying which number is which.
2. **A partial `--dim` run is in play.** A, R and SM are `not_evaluated`, so `bar_95_pass` cannot be true for structural reasons, and the run is not comparable to a full audit. The FAIL line reads the same as it would on a complete run.
3. **The severity word is unexplained.** "[failing - severe defect or broken guarantee (<7.0)]" is a level label; it does not say whether the level came from a live Jev answer or from the evidence-calibrated heuristic the docstring describes for unmatched answers. Those are different claims about the repo.

That is #454's exact class: a gate that passes or fails on something other than the thing it names, with the deciding fact invisible.

**Why not cured here:** the honest cure needs a decision on the display contract - whether the gate line must show `deterministic_mean | jev_level | source_of_level` separately, or keep one number with a provenance suffix. Both are one-line-per-row changes at `audits/self/audit.py:1838-1846`, but they change what a gate receipt *means* across every dimension, so it is a reviewed change with its own gate, not a drive-by.

**Housekeeping:** `--dim SD` rewrites the tracked `audits/self/round2_scores.json`; a partial run therefore leaves a misleading 4x10.0 artefact on disk. Reverted here (`git checkout -- audits/self/round2_scores.json`). Worth a guard (refuse to write scores on a partial `--dim` run, or tag the file with the dims evaluated).
