# Scope the no-writes assurance to the refused round

Part of #683, finding 17 (P2). Verified against `main` `8fc28a0e` on
2026-11-25: still present.

## What is present

`harness/lifecycle_guards.py:462-463` renders an unconditional assurance:

```python
"**Autonomous Waist Gate Guard:** this request was held before any "
"file was written. Nothing was saved and nothing ran.",
```

The renderer is `render_refused_plan(prompt, reason, stages=None, nodes=None)`
(`harness/lifecycle_guards.py:337`). It takes no prior-round state, and
`harness/edit_lifecycle.py` calls it from the `refused` callback.

## Why it matters

`harness/orchestrator.py` `drive()` calls `execute_plan(plan)` for earlier
rounds and only then invokes the `refused` callback when a later `plan_round()`
refuses. By that point edits from the earlier rounds are already on disk, and
`_refused_edit()` does not roll them back. The operator is told:

> this request was held before any file was written. Nothing was saved and
> nothing ran.

which is false for that worktree. The claim is the guard's whole value: if it
can be printed when writes did happen, an operator cannot use it to decide
whether to trust the tree.

## Requested fix

Pass prior execution state (how many rounds ran, which targets they touched)
into the renderer and qualify the assurance to the refused plan only. When
earlier rounds executed, say what remains written instead of asserting nothing
was.

## Acceptance

- A refusal after at least one executed round names the executed rounds and
  does not claim nothing ran.
- A refusal before any execution keeps the current unconditional wording.
- A hermetic test drives one executed round plus one refused round and asserts
  the rendered text.
